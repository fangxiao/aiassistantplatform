# 技术设计 · 组织上下文包(021 · 对应需求 016)

- 文档版本:v0.1(20261006,与需求 016 同轮,方向确认中)
- 关联:008-knowledge-base(KB 基建全复用)、010-workbench(挂载交互)

## 1. 核心决策:标记位 + 模板,不建新表

上下文包 = 共享 KB 加 `is_context_pack` 标记 + 预置结构 + 批量挂载入口。
零新模型(除一列),检索/成员/挂载链路全部沿用——差异化在**产品叙事与结构引导**,
不在机制(对标千问的最低成本路径)。

## 2. 数据模型(迁移:knowledge_bases.is_context_pack bool default false)

预置分区即四篇 KbDocument(创建时事务内写入):
`术语表` / `业务规范` / `决策记录` / `常用联系人`,各带填写说明模板文本。

## 3. API(kb 路由增补)

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/kb/kbs` 增参 `context_pack: bool` | true → 建包+预置四文档(202) |
| POST | `/kb/kbs/{id}/mount-batch` | body {plugin_ids: []} 批量写入插件默认挂载 |

批量挂载实现:插件级 mounted_kb_ids 存在插件 manifest(jsonb)——写 manifest 的
`mounted_kb_ids` 数组(deploy 已有单插件挂载路径,抽出复用);会话创建时继承插件默认。

## 4. 前端

- 知识库页新建弹窗:类型单选(普通库/组织上下文包);选包 → 名称+描述 → 建成跳详情
- 包详情:四分区文档列表直排(点击即编);右上「挂载到助手」多选弹窗(复用助手列表)
- KB 列表徽标 🏢;成员管理沿用

## 5. 测试要点

- 建包:标记位+四文档事务落库;普通建库不受影响
- 批量挂载:manifest 写入、幂等(重复挂不重复写)、权限(仅 admin/owner 可批量)
- 检索:挂载后 kb_search 命中(E2E:问术语→答案含模板内容)
- web vitest:新建类型切换、徽标渲染
