## 1. 一页总览

**AgentPlatform 是一套可私有化部署的企业智能体平台**:让企业以插件生态的方式,
为各业务部门运行定制化 AI 助手——数据留在企业内网,模型自主可控,能力持续生长。

| 项 | 说明 |
|---|---|
| 形态 | Docker 容器化四件套(PG + Redis + API + Web),30 分钟单机部署 |
| 数据 | 全部留在企业内网(会话/知识库/密钥/日志),零外部依赖 |
| 模型 | 接企业自有模型网关或任意 OpenAI 兼容供应商(DeepSeek/火山方舟/Ollama 本地模型等),密钥加密存储 |
| 通道 | Web 工作台 + 飞书(机器人/扫码登录/22 种消息组件映射) |
| 扩展 | 开放插件生态:插件可内部开发、可复用平台注册表沉淀的公共技能与工具(PDF 解析/网页搜索/知识检索/图片生成等,随交付持续累积) |
| 治理 | 角色层级、助手发布审批、邀请码注册、设备管理、操作审计 |

**与公有 SaaS 智能体产品的本质区别**:后者把贵司数据沉淀在厂商云端、能力由官方供给;
AgentPlatform 把平台本身交给贵司——数据、模型、能力扩展权全部自主。

## 2. 企业痛点 → 平台能力映射

| 企业侧痛点 | 平台对应能力 |
|---|---|
| 数据不能出域(合规/商业机密) | 整体私有化部署,数据库/向量库/文件全在内网 |
| 公网 AI 工具能力固定,不贴业务流程 | 插件按业务定制(评审/审查/填报/巡检),富交互 22 种组件直连业务动作 |
| 各部门需求零散,IT 排期排不上 | 插件开发 AI 辅助闭环(CLI 工具链),交付周期以天计 |
| 员工不会写 Prompt,用不起来 | 助手封装了流程与知识,员工在飞书/Web 上像用普通系统一样使用 |
| 知识散落在文档/聊天/系统里 | 知识库(向量混合检索)+ 组织上下文包(术语/规范/决策/联系人四分区,一键挂载到一组助手) |
| 担心 AI 乱来 | 危险操作白名单 + 确认框、发布审批、操作审计、限频与账号锁定 |
| 模型要换/要多家 | 供应商管理(验证连通/模型发现/一键切换),会话级模型选择 |

## 3. 核心能力详述

### 3.1 智能体运行平台

- **助手与会话**:插件即助手;会话支持多模态输入(文档/图片)、断线自动续跑、
  长对话上下文自动压缩、错误自动分类与重试
- **任务与交付物**:手动会话可「保存为任务」;定时任务(日报/巡检/监控)自动运行,
  产出登记为交付物(报告/图片/页面),任务面板统一管理,可推送飞书
- **知识增强**:助手挂载知识库后自动检索引用;支持文档上传、文本直存、
  GitLab 等数据源定期同步

### 3.2 插件生态(与封闭产品的本质差异)

- **skill/tool 注册表**:平台级公共能力池(PDF 解析、网页搜索、知识检索、
  图片生成、HTML 渲染等 16 项起步,随交付持续累积),插件以语义化版本声明依赖、自动组合,
  一次开发全员复用——能力资产在企业内**累积**而非重复采购
- **开发工具链**:CLI 提供 init / validate / dev / test / deploy 全闭环,
  原生支持 AI 辅助开发(Claude Code 等),新插件交付以天计
- **发布治理**:插件需管理员审批后对全员可见;未过审仅开发者可见

### 3.3 富交互组件(22 种)

对话不再只是文字:表单、下拉选择、评审打分、确认卡片、进度条、文件卡片、
图表等 22 种组件,让「AI 收集结构化信息 / 触发业务动作」成为可能——
面向非技术员工的产品化界面,而非 Prompt 游戏。

### 3.4 通道与触达

- **Web 工作台**:任务中心 / 知识库 / 数据洞察 / 管理后台
- **飞书**:机器人单聊与群交互(22 组件自动映射)、定时任务产出推送、
  扫码登录、频道广播
- **CLI / API**:开发者自助部署调试;PAT 令牌支持自动化集成

### 3.5 模型策略(自主可控)

- 平台网关统一接入(OpenAI 兼容),或各部门**自带供应商**:
  预设火山方舟 / DeepSeek / 硅基流动 / OpenAI / Anthropic / 自定义,
  保存即验证连通并发现可用模型,密钥 Fernet 加密、仅本人可用
- 会话级模型切换,智能路由(auto)开箱即用
- 支持内网本地模型(Ollama 等,含 Embedding)

## 4. 交付方案

### 4.1 架构与要求

```
企业内网服务器(Docker Compose)
├── postgres(业务数据 + pgvector 向量检索)
├── redis
├── api(FastAPI 服务端)
└── web(Next.js 工作台)
    端口:3000(Web)/ 8000(API)
```

- 最低配置:4C8G / 100G,可出内网访问模型 API(或全内网本地模型)
- 可选:域名 + HTTPS、SearXNG 联网搜索栈、飞书自建应用

### 4.2 交付内容与周期

| 交付物 | 周期 |
|---|---|
| 平台基线部署(四件套 + 模型接入 + 管理员初始化 + 验收) | 0.5 天 |
| 组织上下文包搭建(术语/规范/决策/联系人导入) | 1–2 天(视材料) |
| 首批定制插件(按业务场景,如文档评审/周报生成/合同初审) | 每场景 2–5 天 |
| 管理员与开发者培训(插件开发/治理操作) | 0.5 天 |

### 4.3 验收标准(部署完成即检查)

- `/status` 诊断页全绿(LLM / Embedding 连通)
- 注册-登录-对话全链路;邀请码与角色门槛生效
- 指定助手完成一次真实业务任务并产出交付物
- (如配)飞书机器人响应、定时任务按计划运行

### 4.4 运维

- 升级:`agentplatform upgrade` 一键重建 + 数据库迁移;内网走离线发布包
- 备份:`deploy/backup.sh`(建议 crontab 每日)
- 监控:平台自带诊断页(六项健康检查)与成本/用量洞察面板

## 8. 常见问题

**Q:和大厂的智能体工作台(豆包工作/千问办公/WorkBuddy)比,为什么选你们?**
A:它们是公有云产品:数据在厂商侧、能力由官方供给、无法私有化。当贵司需要
数据不出域 + 按自己业务定制能力 + 自有模型时,只有私有化平台可选。

**Q:我们 IT 力量薄弱,插件谁来开发?**
A:三种方式任选——我们定制开发(项目制)、贵司业务人员经培训自助开发
(平台开发工具链为 AI 辅助设计,门槛以「会描述需求」计)、两者结合。

**Q:模型费用怎么算?**
A:平台不收模型差价——直连贵司自有网关/供应商账号,费用发生在贵司与模型
供应商之间,平台只做路由与管理。

**Q:后续你们不做了怎么办?**
A:平台代码随私有化部署完整交付在贵司环境,含数据库与运维脚本;
维保是可选项而非生存依赖。
