## 1. 背景与目标

### 1.1 背景
当前 AI 助手应用大多将"助手能力"与"agent 运行时"耦合,底层能力难以复用,且每个助手是自包含孤岛,skill/tool 无法跨助手共享。本平台将 agent 底层能力下沉为平台底座,并将 skill/tool 提升为可复用的平台资源,各助手以插件形式编排调用,实现能力可插拔、可复用、可组合。

### 1.2 目标
- 提供统一的 agent 底层运行时(上下文、调度、LLM 调用、tool 执行、插件加载)
- 构建**可复用的 skill/tool 生态**:skill/tool 为平台级资源,插件声明依赖并显式调用,避免重复实现(第一特色)
- 支持助手以插件形式开发、注入、组合(仅 skill,或 skill + tool)
- 提供 AI-native 开发闭环:开发者用 Claude Code + 平台 CLI/SDK 开发部署插件
- 提供通用对话 WebUI,且对话内容可由插件定义富交互组件
- 面向开发者(开发插件)与使用者(选用助手)两类用户

### 1.3 成功标准
- 「PDF 解析」等 tool 一次开发,被 **≥2 个助手复用**,新助手开发只写领域特有部分
- 开发者在独立仓库用 Claude Code + CLI 完成插件开发-调试-部署,**`init → deploy` 核心命令 ≤ 5 步**,部署后即可被使用者调用
- 使用者登录后能浏览可用助手并对话,对话中可呈现插件定义的富交互组件
- 平台通过 OpenAI 兼容协议接入 LLM,可在不同模型端点间切换,**端点切换不影响已部署插件**
- **MVP-0 核心闭环可演示**:单插件 + 1 skill + 1 tool + 纯文本对话 + function-calling 显式调用跑通

## 2. 用户角色

### 2.1 平台管理员(Operator)
- 配置平台运行参数(LLM 端点与 API 密钥、部署形态)
- 维护平台内置 skill/tool 注册表
- 处置危险/违规插件(禁用、下架)
- 管理使用者与开发者账号

### 2.2 开发者(Developer)
- 在独立仓库开发插件(声明依赖的 skill/tool、编写自有 skill/tool)
- 用 Claude Code + 平台 CLI 开发、调试、部署
- 启停、卸载、调试自己部署的插件;可贡献 skill/tool 到公共资源池
- 管理自己插件的版本与生命周期

### 2.3 使用者(End User)
- 登录平台
- 浏览/搜索可用助手
- 选择助手并对话
- 在对话中与富交互组件交互

> 角色关系:MVP 阶段管理员可由开发者兼任(单机/内部部署场景);三类角色的权限边界在 §8 标注。

## 3. 核心概念

| 概念 | 定义 |
|------|------|
| 平台(Platform) | agent 底层运行时,提供上下文管理、调度、LLM 调用、tool 执行、插件加载、skill/tool 注册表 |
| 插件/助手(Plugin/Assistant) | 以插件形式注入平台的助手能力,独立仓库开发,声明依赖并编排 skill/tool,可被使用者选用 |
| tool | **平台级可复用**的确定性编程接口(函数),直接调用代码并返回结果,如 `pdf_parse(file) -> text` |
| skill | **平台级可复用**的能力/知识单元(行为定义,通常含 prompt 模板),参数化执行;简单形态一次 LLM 调用完成,复杂形态可作为子 agent 多轮完成,如 `summarize(text, style) -> summary` |
| skill/tool 注册表 | 平台维护的公共 skill/tool 资源池,支持版本、来源、权限管理 |
| 显式调用 | agent 通过 function-calling 扩展,结构化地调用 skill/tool(模型 C),结果回填 |
| 富交互组件 | 插件可在对话中定义的 UI 元素(复选框、文本框、按钮等),超越纯文本 |
| 插件 SDK / 部署 CLI | 平台提供给开发者的开发套件与部署命令,支持 AI 驱动的开发-调试-部署闭环 |

> skill 与 tool 的执行模型、注册表元信息、依赖声明协议见 [../design/002-skill-tool-model.md](../design/002-skill-tool-model.md)。两者在运行时统一映射为 OpenAI function-calling 的 `tools` 参数。

## 4. 功能需求

### F1. 插件开发与管理(开发者)
- F1.1 平台定义插件规范(清单:声明依赖的公共 skill/tool + 自有 skill/tool + 元信息 + 依赖模型)
- F1.2 插件可包含:仅 skill 集合,或 skill + tool
- F1.3 开发者通过部署命令将独立仓库的插件部署到平台(进程内加载)
- F1.4 开发者可查看插件状态、启停、卸载;**启停/卸载/更新对运行中会话的处理见 F1.7**
- F1.5 提供插件调试能力(日志、测试对话)
- F1.6 提供 AI-native 开发闭环:插件 SDK + 部署 CLI(`init / validate / dev / deploy / logs`),输出结构化、可被 AI(如 Claude Code)驱动完成开发-调试-部署
- F1.7 **插件生命周期(MVP)**:
  - 版本:插件清单带 semver 版本;更新通过重新部署新版本实现
  - 启用/禁用:禁用后拒绝新会话;已在进行的会话完成当前轮次后拒绝后续轮次(管理员可强制终止)
  - 卸载:仅当无活跃会话时允许;有活跃会话时需先禁用并等待,或由管理员强制终止后再卸载
  - 热加载:MVP 不支持;旧会话继续使用其发起时的版本直到结束,新会话使用最新部署版本
  - 依赖校验:部署时校验 `depends_on`,缺失或版本不兼容则部署失败并返回结构化错误

### F2. 插件运行时(平台底层能力)
- F2.1 进程内动态加载插件
- F2.2 上下文管理(会话、记忆、多轮)
- F2.3 agent 调度循环(LLM 推理 -> 显式调用 skill/tool -> 结果回填 -> 再推理)
- F2.4 tool 执行(可编程接口调用);危险操作通过配置化允许清单做**尽力而为**的限制(非沙箱,见 §5 安全假设)
- F2.5 插件间软隔离:MVP 仅做命名空间与资源归属隔离,不提供对抗性隔离(见 §5)

### F3. 对话与富交互 UI
- F3.1 通用对话界面(类豆包,标准聊天 UI)
- F3.2 插件可定义对话中的富交互组件(复选框、文本框、下拉、按钮等)
- F3.3 组件交互结果可回传给插件/agent,影响后续对话(回传时序与 agent loop 的关系留设计阶段)
- F3.4 流式输出(LLM 响应流式呈现)

### F4. 使用者助手选用
- F4.1 助手列表(浏览、搜索、分类**已部署**助手);MVP 不含市场分发/审核流程(见 7.2)
- F4.2 选用助手后进入对话
- F4.3 会话历史管理

### F5. 账号与认证
- F5.1 使用者与开发者注册/登录(账号密码)
- F5.2 角色区分(开发者拥有插件管理权限;管理员拥有平台配置权限)
- F5.3 会话归属(用户仅能访问自己的会话)
- F5.4 部署 CLI 的认证:开发者以 API token 鉴权后调用部署接口(token 由开发者账号生成)

### F6. LLM 接入
- F6.1 通过 OpenAI 兼容协议(`/v1/chat/completions`)接入
- F6.2 支持配置多个模型端点(glm、deepseek、minimax 等);端点与 API 密钥由**管理员统一配置**(见 §2.1),不对使用者暴露
- F6.3 插件/助手在清单中指定使用的模型 id,或由平台默认
- F6.4 端点失败时返回结构化错误至前端,**不自动降级到其他端点**(MVP)

### F7. skill/tool 复用与显式调用【第一特色】
- F7.1 平台维护 skill/tool 注册表(公共资源池),独立于插件存在
- F7.2 skill/tool 可被多个插件复用
- F7.3 插件清单显式声明依赖的 skill/tool(公共 + 自有)
- F7.4 agent 运行时通过 function-calling 扩展显式调用 skill/tool,结果回填
- F7.5 (待设计)skill 调用 skill 的组合性(MVP 不支持,预留)
- F7.6 (待设计)skill/tool 来源与权限:平台内置 / 开发者共享 / 插件私有

## 5. 非功能需求

- **性能**:首字延迟取决于 LLM 端点;支持流式;单实例初期满足小规模并发(目标 ≤ 50 并发会话,待压测确认)
- **安全**:**MVP 安全假设为可信开发者 / 内部部署**--进程内加载不提供对抗性隔离,恶意插件理论上可访问进程内资源;tool 危险操作通过配置化允许清单做尽力而为限制;使用者数据隔离(会话/账号隔离);不做沙箱/容器隔离(留待演进)。明确该假设以避免误导设计。
- **可扩展**:插件机制可从进程内演进到进程/容器隔离,且不破坏上层 API
- **可维护**:文档与代码一致;插件规范与 skill/tool 规范版本化
- **可观测**:结构化日志;基础指标(tool 调用次数/耗时、LLM 调用成功/失败/耗时、插件错误);MVP 不做分布式链路追踪

## 6. 技术约束(已确认方向)

| 项 | 选型 |
|----|------|
| 后端 | Python + FastAPI |
| 前端 | React + Next.js |
| 插件机制 | 进程内动态加载(起步,后续可演进) |
| LLM 接入 | OpenAI 兼容协议 |
| 数据库 | PostgreSQL + Redis |
| 部署 | docker-compose 单机起步,架构允许后续扩展 |
| 仓库 | 插件与平台代码仓库相互独立,通过部署命令集成 |

## 7. MVP 范围与非目标

### 7.1 MVP 范围
MVP 分两步交付,与 [../tasks/001-task-breakdown.md](../tasks/001-task-breakdown.md) 的 Phase 1 / Phase 2 对齐:

**MVP-0 · 核心闭环**(对应任务 Phase 1,优先跑通)
- 进程内 Python 插件加载与运行
- skill/tool 注册表 + 平台内置资源 + 跨插件复用 + 显式调用(function-calling)
- 基础对话 UI + 流式输出(纯文本,暂不含富交互)
- OpenAI 兼容 LLM 接入(管理员配置端点,助手指定单一模型)
- 开发者通过 CLI 部署插件 + 启停
- 插件开发 SDK 与部署 CLI(AI-native 闭环)
- 暂不接认证(用最快速度打通"开发-部署-对话")

**MVP · 完整范围**(对应任务 Phase 2,在 MVP-0 上叠加)
- 账号认证(使用者/开发者/管理员)+ 会话归属
- 使用者登录 + 浏览选用助手 + 对话
- 插件定义富交互组件(基础类型:文本框、复选框、按钮)
- 会话历史
- 插件生命周期管理(启停/卸载/版本,见 F1.7)

### 7.2 非目标(MVP 不做)
- 插件进程/容器隔离(后续演进)
- skill 调用 skill 的组合性(MVP 先支持 agent 显式调用,组合性后续)
- 多租户计费、复杂权限体系
- 移动端原生应用
- 插件市场分发/审核流程(初期命令部署)
- 插件跨语言支持(初期仅 Python)
- LLM 端点自动降级/故障转移
- 分布式链路追踪
- 使用者自带 LLM key(BYO-key)

## 8. 决策状态

### 8.1 已确认
- ✅ 第一特色:可复用 skill/tool + 显式调用(模型 C)
- ✅ skill/tool 为平台级可复用资源,独立于插件
- ✅ AI-native 开发:Claude Code + 平台 CLI/SDK 闭环
- ✅ 富交互:声明 + 动态实例化
- ✅ MVP 范围:按 7.1 执行(分 MVP-0 与完整 MVP 两步)
- ✅ 认证方式:账号密码;部署 CLI 用 API token
- ✅ 插件与平台仓库独立,通过部署命令集成
- ✅ 多模型路由:MVP 仅支持助手指定单一模型
- ✅ 部署:docker-compose 单机起步
- ✅ 数据库:PostgreSQL + Redis
- ✅ LLM 密钥归属:管理员统一配置端点与密钥,不对使用者暴露;不支持使用者自带 key(MVP)
- ✅ 角色:使用者 / 开发者 / 平台管理员三类(MVP 管理员可由开发者兼任)
- ✅ 插件生命周期:见 F1.7(禁用拒绝新会话、卸载需无活跃会话、不支持热加载)
- ✅ 安全假设:MVP 为可信开发者/内部部署,进程内加载不做对抗性隔离
