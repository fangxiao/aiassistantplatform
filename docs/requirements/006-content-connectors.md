## 1. 背景与问题

知识库(M12)目前只有两个内容入口:手动上传文件、会话产出入库。真实知识大量存在于外部系统:
产品/项目文档在飞书与 Confluence,技术文档在 GitHub 仓库,公开资料在网页。靠人工搬运
导致知识库陈旧、覆盖不全,检索价值打折。

业界产品(Glean、Microsoft Graph Connectors、Airbyte 等)的共同做法是**连接器**:
以标准化适配层把外部系统内容**增量同步**进平台检索索引。本里程碑只做**内容型连接器**
(把内容"读进来");不做动作型(调外部 API 干活)与通道型(IM 机器人),后两者另行立项。

## 2. 目标

1. 知识库可配置一个或多个**数据源(连接器)**,同步进来的文档自动进入现有
   解析→切分→向量化 pipeline,与手动上传文档在检索层完全同质。
2. 框架与 adapter 分离:同步编排、状态、凭据、调度、删除处理只做一次;
   各外部系统差异收敛在 adapter 内。首批 4 个 adapter:
   **网页/站点、飞书文档、Confluence、GitHub**。
3. 支持「立即同步」手动触发与可选**定时轮询**;增量同步,不做重复全量。
4. 同步内容的可见性**跟随目标知识库**(private/public/shared),不做源系统 ACL 继承(二期)。

## 3. 用户故事

- **U1 配置数据源(开发者/库管理员)**:在知识库管理页为某个库「添加数据源」,
  选择类型、填写连接配置与凭据(如飞书 app_id/app_secret、GitHub PAT、Confluence URL+token、
  网页 URL/sitemap),可测试连接;保存后立即可手动同步。
- **U2 立即同步**:点击「立即同步」,后台增量拉取;UI 显示同步状态
  (运行中/成功/失败)、本次新增/更新/删除文档数与错误信息;失败可重试。
- **U3 定时同步**:数据源可设置轮询间隔(关闭/每小时/每天,默认每天);
  到点自动增量同步;服务重启后调度自动恢复。
- **U4 网页连接器**:配置一个或多个种子 URL,可选 sitemap.xml;抓取页面与同域链接
  (限定深度/数量上限),经既有 html_cleaner 去噪转 Markdown 入库。
- **U5 飞书连接器**:用自建应用凭据拉取指定知识空间/文件夹下的云文档(doc/docx/sheet/wiki),
  文档正文转 Markdown;按更新时间增量。
- **U6 Confluence 连接器**:配置站点 URL + PAT/Basic Auth,按空间 key(CQL scope)拉取页面与博客,
  存储格式 XHTML 转 Markdown,按 version/lastModified 增量。
- **U7 GitHub 连接器**:配置仓库(owner/repo)、分支、路径白名单与文件后缀
  (默认 .md/.txt/.rst),通过 Contents API 增量同步,按 commit SHA 判断变更。
- **U8 删除与下架**:全量型同步(网页/Confluence/GitHub)发现外部文档已删除时,
  对应库文档软删(沿用 kb_documents.status=deleted,检索即时不可见);
  停用/删除数据源不自动删除已同步文档(文档是库资产),但停止后续更新。
- **U9 溯源**:同步文档带数据源溯源(连接器类型、外部文档 id、源 URL、最近同步时间),
  复用 kb_documents 既有 origin/source_app/source_session_id 等溯源字段;
  引用来源时用户可点开原文链接。
- **U10 安全**:凭据加密存储(复用 llm 端点的加密能力),API 不回显密钥;
  网页抓取限同域、限制深度/页面数/单页大小,不访问内网地址与云元数据端点(SSRF 防护)。
- **U11 同质检索**:同步文档与上传文档在 kb_search 中无差别检索,带相同的片段/溯源/权限语义。

## 4. 验收标准

1. 为知识库添加网页数据源并立即同步,种子页面经去噪后可被语义检索命中,结果带来源 URL。
2. 同一文档二次同步:内容未变不产生重复文档/重复 chunk;内容变化后 chunk 更新,
   检索到新内容;外部页面删除后再次同步,该文档检索不到。
3. 飞书/Confluence/GitHub 三类数据源各至少一个真实(或录制夹具)端到端用例:
   配置→首次同步→修改外部文档→二次同步只更新变更文档。
4. 定时同步:设置轮询间隔后,到点自动执行(测试中用缩短间隔验证);重启服务后待执行任务不丢。
5. 凭据:接口任何响应不包含明文密钥;数据库中凭据列为密文;错误配置(错误 token/无权限)
   返回结构化错误且数据源标记 last_status=failed,不影响库内其他数据源与既有文档检索。
6. 权限:同步进 private 库的内容,非授权用户检索不到;改为 public 后全员可检索
   (完全沿用知识库现有权限,无独立 ACL)。
7. 配额:遵守既有单文档 20MB、单库 200 文档配额;超配额文档标记跳过并在同步结果中计数,
   不中断整次同步。
8. 单个数据源同步异常(超时/403/限流)只影响本次该数据源,有错误信息与退避,不拖垮调度器。

## 5. 非功能约束

- **不引入新基础设施**:调度用应用内 asyncio 任务 + 启动扫描(同 kb pipeline 既有模式),
  不引入 Celery/独立 worker;多 worker 部署的分布式调度在文档中标注为已知限制(同 BrowserBridge)。
- **复用既有管线**:同步只负责"取内容 + 产出文档",解析/切分/向量化/状态机/重试全部走
  core/kb/pipeline.py;不另建向量化路径。
- **凭据**:复用 core/llm/crypto 的加密;配置分密文(凭据)与明文(URL/范围/间隔)。
- **网络**:外部请求统一超时、单数据源并发上限、分页;网页适配器 SSRF 防护(禁 localhost/内网段/
  云元数据 169.254.169.254)、重定向上限、robots.txt 遵循(默认开启,可关)。
- **可观测**:每次同步落运行记录(数据源、起止时间、状态、新增/更新/删除/跳过数、错误摘要);
  结构化日志。
- **幂等**:同一外部文档以 (data_source_id, external_doc_id) 唯一对应一个 kb_document;
  同步任务可安全重跑。

## 6. 范围外(后续里程碑)

- 动作型连接器(外部 API 作为 agent 工具;后续可与 MCP/OpenAPI 导入合并考虑)
- 通道型连接器(飞书/Slack IM 机器人)
- 源系统文档级 ACL 继承与身份映射(本期跟随目标库可见性)
- Webhook/实时推送(本期手动 + 轮询)
- 飞书表格/多维表格/附件二进制解析、Confluence 附件、GitHub 非文本文件
- 多 worker 分布式调度锁

## 7. 分期建议(供任务拆解参考,非承诺)

- **P0 框架 + 网页连接器**:数据源模型/CRUD/凭据加密/同步编排/手动触发/运行记录/
  调度器骨架;网页 adapter(sitemap + 同域抓取 + html_cleaner + SSRF 防护)。
- **P1 定时轮询 + GitHub**:轮询调度与启动恢复;GitHub adapter(SHA 增量最规整,先于飞书)。
- **P2 飞书 + Confluence**:OAuth/应用凭据、分页、格式转换各自适配。
