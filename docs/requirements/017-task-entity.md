# 需求文档 · 任务实体化(M28 · Task Entity)

- 文档版本:v0.1(20261006 初稿,方向确认中)
- 对应主需求:001 §F3 增量;M25(需求 014)聚合视图的实体化演进
- 对应设计:[022-task-entity.md](../design/022-task-entity.md)
- 变更记录:20261006 初稿

## 1. 背景

M25 以聚合视图验证了「任务与交付物」需求(工作台任务中心已上线)。聚合层的天然
上限:任务不可命名、不可归档、不可跨会话组织——「我上个月让 agent 做的那批事」
无法作为对象管理。竞品(WorkBuddy/千问)均以任务为一等对象。

## 2. 与 M25 的关系

聚合视图(现状)回答「正在发生什么」;实体化回答「**做过什么、成果归档在哪**」。
M25 的 artifacts/聚合端点全部保留,实体化在其上加持有者对象。

## 3. 用户故事

- 作为使用者,我把一个会话「保存为任务」(命名),交付物自动归集到任务下
- 作为使用者,我打开任务列表:进行中/已完成/归档三态,任务详情 = 会话入口 +
  交付物列表 + 定时绑定(若有)
- 作为定时任务用户,定时任务天然是任务实体的一员(与手动任务同列表)

## 4. 验收标准

- **A1 实体模型**:tasks 表(id/user_id/title/status: active|done|archived/
  session_id 唯一引用/kind: manual|scheduled/source: chat|scheduler/created_at/
  completed_at);定时任务创建时同步建实体(kind=scheduled,绑定 task_id)
- **A2 会话提升**:会话页「保存为任务」→ 建 manual 实体;artifacts 按 session_id
  自动归集(无改动,M25 数据天然可用)
- **A3 任务列表**:工作台任务中心升级:实体列表(进行中/已完成)优先,聚合视图
  作为「未保存为任务的会话」次级区
- **A4 完成与归档**:任务可标记完成(记 completed_at)/归档;完成不删会话不删交付物
- **A5 兼容**:M25 /workbench/tasks 聚合端点保留;存量会话不自动建实体(用户主动提升);
  定时任务新建起同步建实体(存量定时任务一次性回填实体)

## 5. 范围外

- 多 Agent 并行任务的编排实体(子任务/依赖图)
- 任务模板与复用(「再跑一次这类任务」)
- 任务分享/协作(多人在一个任务上)
