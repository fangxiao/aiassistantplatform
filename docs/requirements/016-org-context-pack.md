# 需求文档 · 组织上下文包(M27 · Org Context Pack)

- 文档版本:v0.1(20261006 初稿,方向确认中)
- 对应主需求:001 §F7/§1.2 生态延伸;竞品对标(千问办公「企业上下文」)
- 对应设计:[021-org-context-pack.md](../design/021-org-context-pack.md)
- 变更记录:20261006 初稿

## 1. 背景

千问办公以「企业上下文——让 Agent 懂企业」为核心卖点;平台已有等价基建(共享 KB、
kb mount、kb_search 检索),但停留在「手动建库手动挂」,**没有产品化叙事与结构引导**。
To B 场景(私有化部署)下单靠裸 KB,客户不知道往里放什么、怎么组织。

## 2. 与既有能力的关系

上下文包 **不新建模型**:= 结构化模板引导创建的共享 KB + 批量挂载能力。
kb/KbMember/mounted_kb_ids/kb_search 全部复用(设计 021 §2)。

## 3. 用户故事

- 作为组织管理员,我按引导一次建好「组织上下文包」(术语表/业务规范/决策记录/
  常用联系人四分区预置),团队成员共同维护
- 作为管理员,我把上下文包**一键挂载到一组助手**——新助手上线即懂组织黑话与规范
- 作为成员,我在任意挂载了上下文包的助手里提问,agent 检索到组织级答案(kb_search 既有)

## 4. 验收标准

- **A1 创建向导**:知识库页「新建」增「组织上下文包」类型;选定后预置四分区
  (术语表/业务规范/决策记录/常用联系人)空文档骨架与填写说明;本质是 visibility=shared
  的 KB + `is_context_pack` 标记
- **A2 批量挂载**:上下文包详情页「挂载到助手」多选(我的可见助手)→ 写入各插件/
  会话默认挂载;已在 M14 KbMountModal 交互上扩展
- **A3 成员共治**:沿用 KbMember(admin/member);上下文包在成员知识库列表中带 🏢 徽标
- **A4 检索生效**:挂载后助手对话走既有 kb_search(无新增链路);验收=术语问答命中
- **A5 权限**:挂载与成员管理与共享库一致;白牌入口不暴露管理面
