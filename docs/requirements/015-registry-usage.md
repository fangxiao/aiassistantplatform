# 需求文档 · 注册表运营面:热度与一键引用(M26)

- 文档版本:v0.1(20261006 初稿并当日交付;落地见设计 020 §7)
- 对应主需求:001 §F7(skill/tool 复用生态)的运营增强
- 对应设计:[020-registry-usage.md](../design/020-registry-usage.md)
- 变更记录:20261006 初稿

## 1. 背景

竞品验证「skill 发现/推荐」是被验证的需求(WorkBuddy 技能推荐位)。平台注册表
(第一特色)目前只回答「有什么」(全景清单 + 客户端搜索),不回答「**哪个经过实战
检验**」——新开发者面对同质能力无从选择;引用一个能力需要手工拼
`tool:xxx@^版本` 字符串,摩擦不小。

## 2. 与 001 的关系

细化 001 §F7:复用生态从「可用」走向「可运营」;不改 skill/tool 模型与依赖解析。

## 3. 用户故事

- 作为插件开发者,我在注册表按使用热度判断哪些公共能力可靠,首选经过大量实战的
- 作为插件开发者,我点一下就把能力的 depends_on 声明复制进剪贴板,贴到 plugin.yaml
- 作为远程 CLI 开发者,`agentplatform registry` 输出里能看到各能力使用热度

## 4. 验收标准

- **A1 使用计数**:tool/skill 每次执行成功即 use_count+1(loop 执行层埋点,公共/私有
  均计,幂等失败不抛——不影响执行);迁移加列,存量从 0 起算(不回填)
- **A2 热度透出**:`/api/specs/capabilities`(web+CLI 同源)与 `/api/registry/*`
  响应条目带 use_count;registry 列表支持 `sort=usage`(默认公共资源按热度)
- **A3 一键引用**:web 注册表能力卡片「复制引用」按钮——按当前版本拼
  `tool:name@^major.0` 写入剪贴板,带复制成功反馈
- **A4 热度徽标**:卡片展示使用次数(🔥 N 次;0 次显示「新」)
- **A5 CLI 同步**:`agentplatform registry` 表格加「使用」列

## 5. 范围外(P2 另行评估)

- 用户侧(非开发者)的能力发现露出与「会话级一键挂载」(涉及资源组装的产品概念变更)
- 推荐/分类运营位(编辑精选)、能力评分与评价
- 按时间窗的热度(周榜)与去重口径(当前为调用次数原始值)
