# 需求文档 · 飞书通道(M22 · Feishu Channel)

- 文档版本:v0.1(20260930 用户确认载体:飞书;原意向微信因无合规个人号 API 改道)
- 流程阶段:需求+设计合一(通道型功能,范围收敛)

## 1. 问题陈述

平台助手目前只能通过 Web 工作台使用;用户日常沟通主阵地在飞书,希望直接在
飞书里与平台助手对话,免开浏览器。

## 2. 方案要点(含选型)

- **飞书自建应用 + WebSocket 长连接事件订阅**(不选回调模式:无需公网 HTTPS
  入口,本地 Docker 部署即可接入);
- 通道网关以 API 容器内后台任务运行(settings 开关,未配置凭证不启动);
- 消息桥:飞书单聊文本 → 平台 chat 会话(复用 agent_stream_for_session,
  含 P1 断线检查点)→ 回复文本回飞书;
- 会话映射:`channel_sessions` 表,(channel, chat_id) ↔ session_id,
  同一飞书会话连续对话;发 `/重置` 开新会话;
- 归属:通道统一挂在一个服务账号(role=user)名下;助手选择取
  `FEISHU_DEFAULT_PLUGIN`(可空=默认助手)。

## 3. 用户故事

- **U1 飞书聊助手**:用户在飞书里找到平台机器人应用,直接发消息,
  机器人流式生成后以文本回复;上下文连续(同 chat_id 同会话)。
- **U2 开新话题**:发 `/重置` 开新会话,旧上下文不再影响。

## 4. 验收标准

- A1 配置凭证后容器启动即连上飞书(日志可见),未配置不启动、无报错;
- A2 单聊文本 → 助手回复,内容与 Web 端同源(同一 agent 管线);
- A3 同 chat_id 多轮上下文连续;`/重置` 后上下文清零;
- A4 飞书侧连续发多条时按序处理(不并发跑同一会话);
- A5 会话与消息在 Web 端可见(同一服务账号的会话列表)。

## 5. 范围外(P2+)

- **多机器人配置与助手授权**(20260930 用户提出):凭证从全局 settings 改为
  用户级/租户级配置,多个飞书应用并存、各自长连接;**每个机器人可指定可用
  助手范围(allowlist)**——如团队机器人只开放指定插件,个人机器人全量;
  `/助手列表` `/切换` 按所属机器人的授权过滤;
- **飞书用户 ↔ 平台账号打通**:按发消息人 open_id 映射各自平台账号,
  会话/知识库/权限归各人(现为共享服务账号);
- 群聊 @机器人、富卡片(表格/表单渲染)、文件互传;
- 平台通知推送(定时简报/告警到飞书);
- 通道侧管理操作(审批/启停)。

## 6. 依赖与配置

- 新增 Python 依赖:`lark-oapi`(飞书官方 SDK,WebSocket 长连接+消息 API);
- settings:`feishu_app_id / feishu_app_secret / feishu_default_plugin`;
- 飞书开放平台:创建自建应用 → 开机器人能力 → 事件订阅选**长连接** →
  订阅 `im.message.receive_v1` → 发布版本(用户操作,见 docs/design/017 附录)。
