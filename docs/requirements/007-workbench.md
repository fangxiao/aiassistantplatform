# 需求文档 · 个人工作台(M14 · Workbench)

- 文档版本:v0.1(草案,待评审)
- 日期:2026-09-14
- 流程阶段:阶段 1 · 需求
- 背景决策:工作站形态采用**路线 A**——直接演进平台现有 WebUI,不另起独立产品;
  平台提供运行时与能力,工作台是平台的前端产品层。拆独立产品(路线 B)仅当需要
  对外品牌化/独立部署时再启动,与知识库外迁同策略(逻辑收口、物理后拆,ADR 0006 同款)。

---

## 1. 背景与定位

平台现有 WebUI 以"对话工作区"为核心(首页即聊天)。工作站类产品(WorkBuddy 等)的
核心体验是**以"我"为中心的今日视图**:打开第一眼看到待办、动态、入口,而不是一个空对话框。

M14 把首页演进为双视图工作台:
- **对话视图**(现有,不动):会话 + 助手 + 富交互;
- **工作台视图**(新增):今日概览 dashboard,聚合平台已有数据,作为日常入口。

**不做**独立后端/独立账号体系;一切数据走平台现有 API(为将来路线 B 拆分守住零成本红线)。

## 2. 目标

1. 打开平台先见"工作台":今天有什么、最近在干什么、一步直达高频动作。
2. 高频路径缩短:继续上次会话、新开会话、问知识库、上传文档 ≤ 1 次点击。
3. 知识库从"要去管理页看"变成"动态推到眼前":同步结果、处理状态、最近文档。
4. 全程复用现有 API,**P0 零后端改动**。

## 3. 用户故事

- **U1 今日概览**:进入平台默认落在工作台视图:问候 + 日期、我的助手快捷卡
  (显示挂载的知识库数)、最近会话列表(点击续聊)、知识库动态卡
  (各库最近同步状态/最近文档/处理中文档数)。
- **U2 快捷操作**:工作台顶部固定操作区:＋新会话(选助手)、📖 问知识库
  (直达选中库的检索调试/新建挂载该库的会话)、⬆️ 上传文档(选库)。
- **U3 会话延续**:最近会话点击 → 携 sessionId 跳转对话视图,无缝续聊(现有参数已支持)。
- **U4 助手直达**:助手卡点击 → 以该助手新开会话;挂库标识帮助用户知道"这个助手懂什么"。
- **U5 知识库动态**:连接器同步成功/失败(最近运行状态与计数)、文档处理中数量
  (轮询已有机制复用),点击进入对应库的管理视图。
- **U6 视图记忆**:用户上次用哪个视图,下次打开默认进入(仅本地偏好,不建表)。
- **U7 每日简报(P1)**:工作台提供"生成今日简报"按钮:由默认助手聚合
  知识库最近变化 + 未完成事项,产出一段结构化 Markdown(复用 session 产出收藏)。
- **U8 待办清单(P1)**:工作台内置轻量待办(勾选/增删);数据存本地存储(纯前端,
  不做多人协作);助手可通过会话"帮我记一条待办"由 output_block 交互添加(交互输入类控件已有)。

## 4. 验收标准

1. 登录后默认视图可配置为工作台;两个视图切换 ≤ 1 次点击,状态互不丢失(会话流不打断)。
2. 工作台各卡片数据全部来自现有 API(assistants/sessions/kb),P0 无后端 diff;
   接口失败时卡片降级为占位,页面不白屏。
3. 从工作台发起"继续会话/新会话/问知识库"三个路径各自 ≤ 1 次跳转即达。
4. 知识库动态能正确展示最近同步时间/状态/计数;有处理中文档时实时刷新(复用 2.5s 轮询)。
5. 待办(P1)刷新页面不丢(本地持久化),不产生任何后端写请求。

## 5. 非功能约束

- 前端仅在 `web/` 内演进;不新建独立前端仓库(路线 B 的拆分边界将来再做)。
- 工作台不引入新表、不绕过平台 API 直查数据(红线,将来拆分零成本的前提)。
- 性能:工作台首屏并行拉取 3 类数据(助手/会话/库),任一慢接口不阻塞整页(卡片独立 loading)。

## 6. 范围外(后续里程碑)

- **主动唤醒/定时任务**(平台级能力:scheduled agent runs,晨报自动推送)——单独立项,
  需要平台新增调度会话的机制,影响面大于本里程碑。
- 日历/邮件/IM 集成(需外部系统动作型连接器,M13 P2 之后的延伸)。
- 团队协作形态(共享待办/任务分派)。
- 移动端适配打磨、桌面壳(Tauri)。

## 7. 分期建议

- **P0 工作台视图**:双视图切换 + 今日概览(助手/最近会话/知识库动态/快捷操作) +
  视图记忆 + 降级容错。纯前端。
- **P1 轻量效率件**:待办清单(本地存储) + 每日简报(按钮触发,复用会话链路)。
- **P2 主动服务**(另行立项):平台定时唤醒 agent 机制 → 晨报自动推送。
