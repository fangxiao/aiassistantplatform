# 需求文档 · 任务面板与交付物(M25 · Task Center & Deliverables)

- 文档版本:v0.1(20261006 初稿并当日交付,方向经确认;落地见设计 019 §7)
- 对应主需求:001 §F3(对话与工作台)的增量演进
- 对应设计:[019-task-deliverables.md](../design/019-task-deliverables.md)
- 变更记录:20261006 初稿 → 同日交付

## 1. 背景

2026 下半年大厂 agent 工作台(腾讯 WorkBuddy、字节豆包工作、阿里千问办公)的产品叙事
已从「对话」切换到「任务与交付物」:任务有状态、可并行、有可打开的产出,洞察口径从
token 消耗转向结果交付。

平台现状:产出散落三处——会话消息流(富文本/组件)、task_runs.output(定时任务)、
uploads 目录的文件(html_render/image_gen 签名 URL,**无登记,事后不可枚举**)。
使用者无法回答"我最近让 agent 做成了哪些事、产物在哪"。

## 2. 与 001 的关系

细化 001 §F3:工作台从「会话列表」升级出「任务视角」;不改变会话/消息模型本身
(任务实体化留后续,见 §5)。

## 3. 用户故事

- 作为使用者,我在工作台一眼看到三件事:正在跑的任务、定时任务的下次运行与近况、
  最近产出的交付物——不用翻会话列表找产物
- 作为使用者,交付物(报告/图片/HTML 页面)点击即开、可跳回产生它的会话继续追问、
  可存入知识库
- 作为定时任务用户,任务产出已经在任务维度组织,希望与手动会话的产物出现在同一视图

## 4. 验收标准

- **A1 任务面板**:工作台新增「任务中心」区,三栏:进行中 / 定时任务 / 交付物;
  数据一次拉取(单聚合端点)
- **A2 交付物登记**:`tool:html_render`、`tool:image_gen` 产出自动登记;定时任务成功
  产出登记为报告条目;登记失败不影响工具原返回(闭环自愈)
- **A3 交付物操作**:列表含类型/标题/时间/来源助手;点击打开(展示时现签 URL,不存
  过期签名);「跳转会话」继续追问;「存知识库」(复用现有 SaveToKb 链路)
- **A4 聚合端点**:`GET /api/workbench/tasks` 返回三栏数据;仅本人(user_id 过滤);
  白牌 `/a/{token}` 入口不暴露
- **A5 兼容与边界**:存量产物不回填,自上线起登记;task_runs.output 以「报告」条目
  呈现(跳会话);交付物仅本人可见,分享/协作不在本期

## 5. 范围外(P2+/另行立项)

- 任务实体化(统一 chat 会话与定时任务为一等任务对象)——先以聚合视图验证需求
- 手动会话完成后的飞书推送(定时任务已有 feishu_chat_id 推送,复用面待任务实体化)
- 交付物版本管理、协作编辑、对外分享链接
- 大厂式多 Agent 并行任务编排(与本平台插件生态正交,另行评估)
