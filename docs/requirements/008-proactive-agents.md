# 需求文档 · 主动唤醒与定时智能(M15 · Scheduled Agent Runs)

- 文档版本:v0.1(草案,待评审)
- 日期:2026-09-15
- 流程阶段:阶段 1 · 需求
- 背景:工作台(M14)已具备完整的"人找功能"闭环(待办/简报/知识库动态),但一切都靠
  用户打开页面手动触发。工作站类产品的标志性体验是**工作来找你**——晨报早上已经在
  那里、异常主动被标红。本里程碑为平台新增**定时唤醒 agent**能力(工作台 P2 的依赖,
  见需求 007 §6)。

---

## 1. 问题陈述

平台现有的所有 agent 运行都由用户消息触发(POST /sessions/{id}/messages)。三类高频
场景因此无法成立:

1. **周期性汇报**(晨报/周报):需要用户记得来点按钮——M14 简报是手动触发的;
2. **周期性巡检**(知识库同步健康度、文档新鲜度):失败只能等用户撞见;
3. **定时提醒型任务**("周五下班前提醒我写周报"):agent 无法在未来某时刻自己醒来。

根因:平台没有"到点自动运行一次 agent"的机制。连接器调度器(M13)只调度**数据同步**,
不调度 agent 推理。

## 2. 目标

1. 用户可创建**定时任务**:到点平台以该用户身份自动运行一次 agent(默认助手或指定助手),
   prompt 由任务定义,资源范围(挂载知识库等)由任务声明;
2. 运行产出(文本为主)落**工作台**:定时简报自动出现在简报卡(标记"自动"),异常运行
   进入通知铃铛;可选自动存入知识库;
3. 调度复用连接器调度器的成熟模式(DB 持久化 + 启动恢复 + running 拒绝重入),不引入
   新基础设施;
4. 定时运行**无交互回填**:遇到 await_external 类交互直接失败落错误(定时上下文无人应答)。

## 3. 用户故事

- **U1 创建晨报任务**:用户在工作台「定时任务」入口新建:名称、提示词(预填晨报模板)、
  执行频率(每天 08:00/每周一/自定义间隔)、可选指定助手与知识库范围(默认用户当前可见
  且被助手挂载的库)。保存后任务进入待调度。
- **U2 自动运行与呈现**:到点平台自动创建(或复用)会话运行 agent;文本产出自动成为
  工作台简报(标记"08:00 自动生成"),未读进通知铃铛;产出可选勾选"自动存入知识库"
  (复用 from-text 收藏链路,来源 app=scheduler)。
- **U3 任务管理**:列出我的定时任务(下次运行时间/最近状态/最近产出摘要);支持启停、
  手动跑一次、编辑、删除;查看每次运行记录(状态/耗时/产出全文/错误)。
- **U4 失败可见**:运行失败(模型错误/资源不可用)→ 任务标记 failed + 通知铃铛红色条目
  + 错误摘要;到点自动重试(下个周期),不做即时重试(MVP)。
- **U5 配额与安全**:每用户定时任务数上限(默认 10);单任务单次运行有 token 预算
  (复用现有模型配置,不做单独计费);任务以创建者身份运行——知识库检索范围 = 该用户
  在任务里声明挂载的库(创建时校验可读),不因运行时权限变化而越权(运行时防御性校验同 M12)。
- **U6 停用/删除的语义**:停用后不再调度;删除任务保留历史运行记录(审计)。

## 4. 验收标准

1. 创建"每天 08:00 晨报"任务后(测试用缩短间隔),到点自动产出简报并出现在工作台简报卡,
   带"自动生成"标记;通知铃铛出现对应未读。
2. 服务重启后,待执行任务的调度自动恢复(next_run_at 持久化);错过的时间点(宕机期间)
   不补跑,直接顺延到下个周期。
3. 运行失败(模拟模型不可用)→ 任务 failed + 通知铃铛红色条目;下个周期自动再跑。
4. 任务检索范围隔离:任务声明挂载库 A;把 A 转私有后,运行时该库自动失效(M12 防御分支),
   不报错不越权。
5. 非创建者不可见/不可操作他人任务;API 全部鉴权。
6. 遇 await_external 交互块的任务运行失败落错误,不挂起调度器。
7. 每用户任务数达到上限时创建被拒,错误信息结构化。
8. 手动"跑一次"与到点自动运行走同一执行路径,行为一致。

## 5. 非功能约束

- **不引入新基础设施**:调度复用 M13 模式(应用内 asyncio + DB 持久化 + tick 扫描);
  多 worker 重复触发靠 DB 状态去重(running 拒绝),分布式锁规模化再做(与连接器同注记);
- **复用会话链路**:定时运行 = 平台自动创建会话 + 发送任务 prompt(与 M14 简报同链路),
  产出物天然可追溯(session_id);不新建"无头运行器";
- **成本可见**:每次运行记录耗时与产出长度;任务列表展示最近运行情况,防止失控;
- **凭据**:任务不存储新凭据,全部复用用户/平台既有配置(模型端点、知识库权限)。

## 6. 范围外(后续里程碑)

- 插件声明的定时能力(plugin.yaml schedules,由开发者而非用户定义)——本期只做用户级任务;
- Webhook/邮件/IM 推送(等通道型连接器);
- 条件触发(事件驱动"仅当同步失败才运行")——本期纯时间调度,通知分级由产出内容承载;
- 复杂编排(多步骤任务链、任务依赖 DAG);
- 即时重试与退避策略(本期到点重跑)。

## 7. 分期建议

- **P0 定时执行闭环**:scheduled_tasks/task_runs 模型 + 调度执行器(复用连接器调度模式)
  + 任务 CRUD API + 工作台「定时任务」管理卡 + 产出落简报卡(自动标记)+ 运行记录;
- **P1 体验完善**:通知分级、自动存知识库开关、创建时的晨报/巡检模板、任务配额;
- **P2 生态扩展**:插件声明定时能力、通道推送(依赖通道型连接器)。
