# agentplatform 产品愿景与定位

- 文档版本:v1.0
- 日期:2026-08-11
- 用途:设计阶段的 north star,所有架构与实现决策以此为准

---

## 1. 一句话定位

**让开发者用 AI 快速开发带富交互的可分发助手;让使用者在垂直场景获得定制化、结构化的助手体验。**

## 2. 核心特色(按重要性排序)

### 特色一:可复用的 skill/tool + 显式调用【第一特色】
- skill 和 tool 是平台级**一等公民、可复用资源**,独立于插件存在
- 插件**显式声明依赖**公共 skill/tool + 自有部分
- agent 通过 **function-calling 扩展(模型 C)** 显式调用 skill/tool,结构化、非黑盒
- **网络效应**:skill/tool 越多,新插件开发越快(类比 npm / Unix 组合)
- 例:「PDF 解析」tool 一次开发,PRD 评审 / 合同审查 / 论文摘要助手均可复用

### 特色二:AI-native 开发体验
- 开发者用 Claude Code + 平台 CLI/SDK 开发插件
- CLI 提供 `init / validate / dev / deploy / logs` 闭环,输出 AI 友好
- 平台提供插件开发规范,让 AI 自主完成开发-调试-部署
- Claude Code 是开发工具,平台是运行/分发载体,互补不竞争

### 特色三:富交互对话
- 插件可定义富交互组件(声明 + 动态实例化)
- 超越纯文本,适合结构化交互场景(评审打分、配置填写、表单采集)

### 特色四:开放插件生态 + 可私有化
- 任意开发者可开发部署助手
- 可私有化部署,面向垂直/企业场景,数据不出域

## 3. 不做什么(防止定位漂移)

- 不和 Claude Code 争"开发者自用简单任务"(那种场景 Claude Code 直接做更快)
- 不和豆包拼消费级助手数量、工程成熟度、免费
- 不做纯文本对话平台(那是豆包的领域)

## 4. 目标用户与场景

| 用户 | 价值 |
|------|------|
| 开发者 | 用 AI 快速开发可分发、带富交互、可复用底层能力的助手 |
| 使用者 | 在垂直场景使用结构化定制助手(PRD 评审、配置生成、表单采集等),而非通用闲聊 |

## 5. 差异化对比

### vs Claude Code(开发工具,互补)
- Claude Code 适合开发者自用、纯文本、一次性任务
- 平台适合产品化、富交互、分发给非技术用户、复用 skill/tool
- 二者组合:用 Claude Code + 平台 CLI 开发插件 -> 部署到平台

### vs 豆包(消费级,差异化)
- 豆包:封闭、官方助手、纯文本为主、消费级、海量免费
- 平台:开放插件、富交互、可私有化、垂直定制
- 不正面竞争,聚焦豆包覆盖不到的、需要定制+结构化交互的场景

## 6. 关键设计决策(已对齐)

| 决策 | 选择 |
|------|------|
| skill/tool 模型 | 模型 C:function-calling 扩展,声明依赖 + agent 显式调用 |
| 仓库 | 插件与平台独立仓库,部署命令集成 |
| 富交互 | 声明 + 动态实例化 |
| LLM 接入 | OpenAI 兼容协议 |
| 技术栈 | Python(FastAPI)+ React(Next.js)|
| 插件加载 | 进程内起步,可演进到隔离 |

## 7. 挑战与应对

| 挑战 | 应对 |
|------|------|
| 富交互工程复杂度 | 分阶段,先基础组件类型(文本框/复选框/按钮) |
| 开放插件安全 | 进程内起步 + tool 危险操作限制,规划隔离演进 |
| 生态冷启动 | 种子场景(PRD 评审类)做透,先证明价值 |
| 与豆包体验差距 | 靠差异化(开放+富交互+定制)而非全面对标 |
