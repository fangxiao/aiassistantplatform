# ADR 0011 · 上下文压缩采用单滚动摘要,而非分段摘要/全文截断

- 状态:已接受(2026-09-29)
- 关联:需求 011 H3 / 设计 016 §4

## 背景

多轮会话无上下文管理,token 随轮次线性膨胀:响应变慢、易触发上游窗口超限。
需要压缩策略,且压缩自身的 token 成本须可控。

## 决策

1. 触发:会话 token 估算 > 端点窗口 × 阈值(默认 0.7,可配置);
2. 策略:保留 system prompt + 最近 N 轮(默认 6)原文,更早轮次合并为**单条
   滚动摘要**(一次低温度 LLM 调用),以 `MessageRole.summary` 行固化;
3. 增量滚动:下次压缩 = 旧摘要 + 新淘汰轮次 → 新摘要,不重复摘要全量历史;
4. 摘要 prompt 固定要求"用户声明的约束与偏好逐条保留",验收用例守护。

## 备选与理由

- **纯截断(丢弃早期历史)**:零成本但丢信息,用户约束类内容丢失直接劣化回答,
  违背"长会话不劣化"目标;
- **分段多摘要(map-reduce 式)**:检索精度略高,但摘要调用次数与成本随轮次增长,
  且平台场景(单助手连续对话)无需多段检索;单滚动摘要一次调用、增量维护,
  成本可算(非功能约束 4);
- **压缩放客户端**:历史权威在服务端,客户端压缩不可信也不可迁移。

## 后果

- messages 表新增 `summary` 角色(alembic + MessageRole 枚举),
  渲染层需跳过该角色;工作台提供"查看上下文摘要"入口;
- 单会话摘要调用频率上限(默认 10 分钟 1 次)防止反复触发;
- 摘要质量依赖模型,压缩事件落 trace 便于用真实会话复盘。
