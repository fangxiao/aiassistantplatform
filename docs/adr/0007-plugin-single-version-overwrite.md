# ADR 0007 · 助手(插件)不做多版本管理,同名部署原地覆盖

- 状态:已接受
- 日期:2026-09-11
- 背景:原设计(001 §F1.7 / 002 §F-ST-7 / 设计 006 v0.1)中,插件按 `(name, version)` 唯一,
  每次部署新版本都新增一行,历史版本长期堆积;助手广场只能查询时按名称去重、只展示最新。

## 决策

**助手名(`plugins.name`)全局唯一,最新部署覆盖原有的,不保留历史版本。**

- 同名重部署为原地 upsert:保留行 UUID 与首次部署者 owner_id,替换 manifest / version 标签 /
  deployed_at,状态重置 active;
- 先清掉该插件名下全部私有注册表资源(含旧版本),再登记本次资源;重建代码存储目录;
- 历史会话经 `sessions.plugin_id`(无 DB 外键)引用保留的同一行,不悬挂、自动获得新版本;
- `version` 仍是 manifest 必填 semver,但仅作"最近部署版本"展示标签,不参与唯一性与解析。

## 边界:公共注册表资源不动

平台 builtin/shared 的 skill/tool/kb 资源**仍按 `(id, version)` 多版本并存**,
depends_on 的 `^`/`~` 约束与 T11.10 可选依赖/回退语义不变——这是平台第一特色
(细粒度能力复用)的版本基础。本次只去掉"助手分发单元"的多版本。

## 理由

- 平台定位为可信开发者内部部署(001 §5),没有"用户侧选定助手历史版本"的产品需求,
  多版本只带来堆积、去重展示与 `overwrite` 参数等复杂度;
- 原地覆盖 + UUID 稳定,升级心智最简单("重新部署即生效"),且历史会话零成本延续;
- 会话无 FK 约束,迁移可安全地把旧版本会话重映射到保留行。

## 后果

- 部署接口不再有"已存在 422"与 `overwrite` 参数语义;CLI 始终按名覆盖;
- 迁移对存量数据按 name 保留最新行、重映射 sessions、清理旧版本私有资源;
- 回滚不可逆(历史版本行删除),内部平台阶段可接受;
- 多租户化时需补"同名覆盖"的权限校验(当前不做,YAGNI)。
