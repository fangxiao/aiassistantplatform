# ADR 0009 · 断线恢复采用轮次边界草稿消息,而非逐 token 持久化

- 状态:已接受(2026-09-29)
- 关联:需求 011 H1 / 设计 016 §2

## 背景

LLM SSE 流中断(网络抖动、上游故障、进程重启)导致整轮回复丢失:
助手消息仅在流正常结束时落库,异常路径 rollback。用户需手动重发消息,
已完成的多轮工具调用与 token 计费全部作废。

## 决策

1. **检查点粒度 = 轮次边界**(发起下一次 LLM 调用前 / 每次工具执行后),
   而非逐 token/逐 chunk 持久化;
2. 载体为**草稿消息行**(`messages.is_draft`),每轮边界 flush + commit,
   断线时天然留存;续跑以 `resume` 端点从草稿重建,仅重跑未完成轮次;
3. 前端按 `resume_of` 原位替换草稿渲染。

## 理由

- LLM 无字节级续传能力,精确断点续传不可实现;轮次级重放是能落地的最优近似;
- 逐 token 写库在高频流下 I/O 成本不可接受,轮次边界(每轮 1-2 次 flush)开销可忽略;
- 工具调用结果随草稿持久化,重跑免重复计费(工具是 token 成本大头);
- 与现有"用户取消保存 partial"行为一致,不引入第二套部分落库机制。

## 后果

- 断线重放会重新生成未完成轮次的少量文本(轮次内 delta 级重复),可接受;
- `build_history` 对草稿行无需特判(草稿即部分回答,历史一致);
- 新增 `resume` 端点与前端替换逻辑,复杂度集中在 API 层,loop 改动小。
