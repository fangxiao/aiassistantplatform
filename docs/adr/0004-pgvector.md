# ADR 0004: 知识库向量存储选用 pgvector

- 状态:已接受
- 日期:2026-09-05
- 关联:需求 005、设计 008 §1/§3

## 背景

知识库(MVP)需要向量检索能力,候选方案:pgvector 扩展 vs 独立向量库(Qdrant/Milvus)。

## 决策

选用 **pgvector**,作为 `core/kb/retriever.py` 的默认后端实现。

## 理由

1. 平台底座已是 PostgreSQL + Alembic,pgvector 零新增运维组件,单机/内部部署形态友好(与 001 的 MVP 部署假设一致);
2. MVP 规模(单库 ≤ 5 万 chunk)远低于 pgvector 能力边界,cosine + HNSW/IVFFlat 足够支撑 NFR-1(P95 ≤ 800ms);
3. 检索与权限过滤(3.3)在同一 SQL 内完成,避免跨存储的一致性与双重鉴权问题;
4. 需求 NFR-3 要求检索后端可替换——接口收口在 retriever,规模瓶颈出现时可平滑迁移,不影响上层 API 与插件。

## 后果

- 迁移中需启用扩展并固定 embedding 维度;维度变更需全量重算并发布新 kb 版本(008 §10 风险 1);
- 超大规模(亿级)或复杂 ANN 调优需求出现时,需评估迁移到专用向量库——届时有明确切换点,非技术锁定。
